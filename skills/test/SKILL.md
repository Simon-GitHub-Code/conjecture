name: test
description: "Find and run the cheapest check that would tell an idea apart from its alternative. Use for 'how would we know', 'test it', 'can we check that', 'prototype it', 'run the numbers'."
---

Call the Skill tool with "lexicon" if it isn't already loaded. Read `IDEA.md`.

Argument tells you whether an idea hangs together. A **test** tells you whether it holds up. Pick the one whose answer arrives soonest.

1. **Predict first.** Write under `## Test` what the idea predicts and what the alternative predicts in one situation. If they predict the same thing, it isn't a test; find where they part.
2. **Make it small.** Shrink it until it can be done today: a script on real data, a quick prototype, a search for evidence someone already gathered, five customer emails, a worked example on paper.
3. **Run it.** If the idea is testable, the test is something in the world: run the code, pull the numbers, look. If it isn't testable by observation (a plan, a design, an argument, a moral view), the test is a worked example or thought experiment carried all the way through, with no step skipped.
4. **Doubt the result.** One sample, a confound, a prediction tweaked after the fact: say what could make the result misleading.
5. **Record it** as `- Result:` with where the evidence lives. If it went the alternative's way, add it as a criticism under `## Criticism` and let the person decide how to answer it.

Done when the result and its evidence are recorded.

**Reply:** what happened and what it means for the idea, then how you found out, then what could make it misleading.
